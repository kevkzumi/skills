Implement the supplied spec or issues, then obtain separate Standards and Spec reviews through the other coding tool before the final implementation commit. The current session owns all edits and completion actions.

This beta supports Codex and Claude Code authors, routing review through the opposite CLI. It requires Python 3.9+, Git, an authenticated reviewer CLI, and a repo-backed installation. Resolve this skill's real directory through any symlink, then read the shared [handoff contract](../../../scripts/cross-review.md). Its sibling executable and the existing review criteria are required; copying this skill folder alone is insufficient.

1. Fetch supplied issue references through the project's issue tracker and state their titles. Resolve the spec from those issues, an explicit source, or matching project specs. If none is found, ask the user for it; only their confirmation permits a recorded Spec skip. Search for all applicable standards and instructions, including `CODING_STANDARDS.md` and `CONTRIBUTING.md` when present. Follow their references and supply their full contents to review.
2. Before editing, run the handoff's `begin` command with a dedicated artifact directory outside the project. Identify the author from the actual coordinating session; pass `--author` only for that verified tool and preserve any user-requested reviewer model override. Capture explicit ownership paths for a dirty start, preserving unrelated work. Stop on ambiguous context, unsupported tools, or ownership conflicts.
3. Call the Skill tool with "tdd" where appropriate, at pre-agreed seams. Implement the requested scope. Run relevant focused checks during development and the full relevant suite at completion. Intermediate commits are included in review from the original baseline.
4. Pause edits and run `review` with the resolved spec and every relevant standards source. The shared handoff exports the complete implementation, including staged, unstaged, and untracked changes, then runs two fresh, concurrent, read-only processes through the opposite CLI. It reads the existing review contract as criteria without invoking its native-agent dispatcher. Do not run the normal `code-review` skill as a substitute.
5. Present Standards and Spec separately, with evidence, references, reviewer tool, and known model identity. A skipped Spec is explicitly skipped, never passed. Assess every finding using the shared handoff: make accepted fixes, validate, record their resolution, and request fresh review of the complete updated implementation. Keep the same session for at most three rounds. Unresolved disagreements, execution failures, or remaining findings after the limit block completion; present the evidence and preserve work and reports.
6. Once review allows completion and validation has passed, run `gate` immediately before the final implementation commit. A changed working state requires fresh review. Use the returned commit paths and the shared contract's scoped staging and commit procedure on the current branch. Report the commit, checks, rounds completed, resolved and remaining findings, disagreements or blockers, each review's outcome, and any live-integration limitations.
